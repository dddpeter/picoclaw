## 2. 关键机制（落地形态）

### 2.1 工具侧：update-only 门（delta-local 检查集）

- **放开的只有树检查**：update-only 批次跳过 root 存在性与可达性（`renderUIEnvelopeViolation`
  的 `!hasCreateSurface` 路径，render_ui.go:354-368）——delta 从不携带整棵树，对增量做 BFS
  只会把每个组件误报"孤儿"；合并树的权威校验在前端 processor 全量重检。
- **保留的 delta-local 检查**：version 前缀 / 恰好一个 union 分支 / 分支键集 / 组件名白名单 /
  组件 id 必查 / **批内重复 id**（:427，delta 内重复同样会在合并树撞车）/ **批内多父引用**
  （:563，按 delta 自身 byID——两个父都在 delta 内是 delta-local 可检不变量，修复轮裁决 §3.1）/
  **单 surfaceId 门**（:339，全批与 delta 一视同仁——pico 合并注册表按 (session, surfaceId)
  键控的前提）/ **256KB 上限**。catalogId 精确匹配只在 createSurface 分支内检查（:330），
  天然"仅对 createSurface 帧生效"。
- **description 三段教学**（:138-175）：分帧形态与 update-only 用法（:145-146 "call render_ui
  again with updateComponents/updateDataModel frames only (same surfaceId, no createSurface)
  — the streamed delta merges into that card"）、VegaChart{spec} 用法与示例（:162-163）、
  交互契约（:166-174：`{path}` 绑定收集表单值 + `[A2UI 交互]` 逐字消息形状 + 完整可回传表单
  示例）。`TestRenderUIToolSchemaContract`（render_ui_test.go:572）锁全部关键短语。
- **组件白名单 19 个**：basicCatalog 18 组件 + VegaChart（:79-85）。错误信息由
  `renderUIComponentNamesDoc` 动态生成，加组件只改集合一处。

### 2.2 pico 注册表与合并广播

- **注册表**：`(chatID, surfaceID) → {messageID, content, frames[]}`（pico.go:431-435），
  chatID 是 pico 会话路由键（"pico:<sessionID>"），A/B 会话同 surfaceId 天然隔离
  （TestPicoA2UI_UpdateOnlyBatch_SessionIsolation 锁定）；LRU 上限 64 表项（:415），
  lookup/record 都 touch（:456/:475）。注册表纯内存——重启清空是接受边界（§6.1）。
- **合并语义与历史折叠同构**：`mergeA2UIFrames`（:528）——components/delete 帧追加、
  updateDataModel 帧按 path 原地覆盖（last value wins）；合并前深拷贝累计帧，广播失败不腐蚀
  注册表状态。两边各自实现、双侧测试钉住（tools 侧 RenderUIHistoryFold / pico 侧同规则）。
- **提交哨兵（修复轮裁决 §3.2）**：`broadcastToSession` 投递前写 seq ring、零连接才返回
  error（`errFrameRetainedNoDelivery` :1365）。update 路径：error 且非 ring 保留 → 保持
  pre-merge 注册表帧（delta 可重试，:690-696）；入 ring 成功（无论有无连接）→ 提交合并帧
  （:697-702）。create 路径：ring 保留也注册且 Send 报成功（:718-739）——报失败会让 render_ui
  重发、复制卡片。
- **孤儿降级（修复轮裁决 §3.3）**：注册表未命中的 update-only 批次**不发 a2ui 键**、降级纯文本
  message.create、不注册（:704-713）。原实现（修复轮之前）降级 create 携 update-only 批会被
  前端 processor 抛 `Surface not found` → 永久占位死卡；现语义与历史折叠的孤儿纯文本一致，
  重启清空边界也优雅（update → 文本行而非死卡）。
- **卡片标题不跟随 update**：message.update 的 payload 固定带 create 调用的兜底 content
  （:683-687）——editMessagePayload 不补 content 会把标题清空，且与历史折叠"caption 钉在
  立卡调用"同语义。

### 2.3 前端 message.update 消费

- **只动 ui，不扰动既有语义**：`parseA2uiFromPayload` 最小形状检查（数组且非空）通过才产出
  新 A2uiInfo，就地替换 ui（protocol.ts:320）；不带/畸形 a2ui → 键不挂，content/kind/toolCalls/
  modelName/attachments 五字段更新语义逐字节不变（protocol.test.ts:267/:296 回归锁定）。
- **found 路径之外**：update 指向未见过的 message_id 时按既有语义追加 assistant 消息，a2ui
  合法时同样挂 ui（:340；TestPicoA2UI 场景外的防御路径）。
- **历史合并去重**：`messageSignature` 补 `ui ? ui.messages.length : 0` 维度（history.ts:197）
  ——REST 历史与 WS 现存消息合并时 ui 变化参与签名（一期延后 minor #18 修复）。

### 2.4 历史回放折叠（RenderUIHistoryFold）

- **输入输出**：调用序的 render_ui 参数 JSON 列表 → 与输入平行的结果数组
  （render_ui.go:741-807）。create 批次立卡（记录 createIdx）；update-only 帧并入；二次 create
  同名取最后一张（丢弃旧卡与已并入更新）；孤儿 update-only 出文本不出卡；当前门拒绝的调用
  （帧检查/大小/delta-local）什么都不出——历史永不重现现行门拒绝的批次。
- **淘汰语义**：折叠卡不过任何门、不受 256KB 约束（live 合并同属性，设计固有——§6.2）；
  updateDataModel 按 path 覆盖（`mergeDataModelFrame` :812，缺 path 与 "/" 分桶合并结果等价）。
- **transcript 接线**：session.go:602-622 先全量折叠再组装，每个 render_ui 调用按序消费一项
  （`nextRenderUIFold`）；折叠预扫与逐调用消费失步时回落单批提取（:614-618 防御路径，
  TestSessionA2UIHistoryFold 系列锁定折叠语义）。

### 2.5 VegaChart 失败分层（三层，全部不炸卡）

1. **spec 未就绪**：`{path}` 绑定尚未被 updateDataModel 灌值（解析为 undefined）或非对象 →
   组件内虚线占位（a2ui-vega.tsx:144）。
2. **编译/渲染失败**：vega-lite 拒绝坏 spec → react-vega `onError` → `console.warn` +
   failed 态占位（:140-143）。
3. **chunk 加载被拒**（网络抖动/重部署后旧 hash 404）：Suspense 只兜 pending 不兜 rejection，
   rejection 会抛给外侧最近错误边界——`VegaChartChunkBoundary`（:104-118）在 Suspense 外侧
   就地拦截，componentDidCatch 上抛 failed 态（修复轮裁决 §3.4——修复前会冒泡到卡级
   A2uiRenderBoundary 把整卡打成占位且无重试路径）。
   **重试语义**：spec 变化（dataModel 更新产生新对象）重置 failed，lazy 实例仅在上一轮
   真失败过时重建（终审收尾：未失败时复用实例——流式 spec 更新不再换组件类型重挂
   VegaEmbed；rejected 的 React.lazy 把拒绝缓存进实例，失败后必须换新实例才能真重试）。

## 3. 修复轮裁决（语义如实记录）

### 3.1 delta 批内多父引用改为拒绝（任务 4 修复轮，a11f73c4）

计划文本"多父引用跳过"指**跨 delta** 引用（挂在既有树上，另一端在前端，delta-local 不可检）；
两个父都在 delta 内的批内多父是可检不变量——放行只能靠前端无反馈兜底，与一期第四次实战
事故同模式。实现把 `renderUIRefCountViolation` 移到 `!hasCreateSurface` 早退之前、按各自
路径的 byID 构建（create 路径全批 / update 路径 delta 自身）。行为对 create 路径零变化；
若误拒（模型合法复用组件——设计上不存在该语义），错误可重试。

### 3.2 "入 ring 即提交"哨兵（任务 5 修复轮，6f3775a0）

`broadcastToSession` 的失败语义以**帧是否入 seq ring**为准：投递前写 ring、零连接才 error。
"失败但已入 ring"的帧会被重连回放，而注册表未提交 → 下次合并缺 delta、视觉丢失。提交点
改为入 ring 成功即提交（无论有无连接）。若判断错了反向代价：无连接时提交了前端没收到的帧
——重连会回放收到，与提交一致，自洽。

### 3.3 孤儿 update 降级选方案 a（任务 5 修复轮，6f3775a0）

注册表未命中的 update-only 批次：不挂 a2ui 键、不注册，fallback 文本承载（message.create
纯文本）。对比方案（降级 create 携 update-only 批）会被前端 processor 抛 `Surface not found`
→ 永久占位死卡，且历史折叠对孤儿 update 本就是纯文本语义——方案 a 让 live/历史一致、
重启清空边界也变优雅（update → 文本行而非死卡）。若判断错：孤儿 update 少了卡但内容仍在
文本里，可回退。

### 3.4 VegaChart chunk 失败组件内降级（任务 6 修复轮，d67c5fd9）

chunk 加载 rejection 原实现落在卡级边界 → 整卡降级且无重试路径。修复：组件内
`VegaChartChunkBoundary`（Suspense 外侧）就地捕获降级，只废图表槽位不废卡；lazy 实例重建
实现真重试；同时收敛 onError warn、loading 占位、独立 mock 测试文件、gofmt 四项次要。

## 4. 实现与计划的偏差

### 4.1 Catalog.derive 不自动保留源 catalog id（任务 6 前置实测项）

计划写"derived catalog 必须保留 basicCatalog 的 catalogId（实测确认；若 derive 改 id，回退
方案=同时接受新旧两个 id）"。实测结论相反：**derive 省略 catalogId 时产出无 id catalog**
（a2ui-vega.tsx:20-23 注释记录）——回退方案落地为"显式传 `catalogId: basicCatalog.id`"
（:190-196）。净效果：派生 catalog 与 wire 消息、Go 白名单共用同一 id，
`renderUIBasicCatalogID` 零调整，无"接受两个 id"的必要。

### 4.2 其余偏差（小）

## 6. 已知局限（含接受边界）

### 6.1 设计裁决固有的接受边界（简要简报点名项）

- **坏 delta 无重试反馈**：update-only 批次跳过树检查后，delta 挂到既有树上被前端 processor
  拒绝（合并树校验失败）时，后端不知情——卡片保持旧状态、模型无重试线索
  （render_ui.go:364-365 注释如实记录）。
- **孤儿 update 纯文本降级**：注册表未命中（重启清空 / LRU 淘汰 / 跨会话乱序）的 update-only
  批次只出文本行，不出卡（§3.3 裁决）。
- **重启清空注册表**：live surface 注册表纯内存（pico.go:437-440 注释）——网关重启后已有卡片
  仍能显示（历史回放折叠重建），但后续 update-only 批次降级文本；模型下次 create 即恢复热更新。
  方向良性：刷新后历史折叠会把该对 create+update 收敛回一张合并卡（live 当时的文本行是
  fire-and-forget 不入 JSONL），历史收敛到"没重启本来会有的状态"。
- **VegaChart 重试仅由 spec 变化触发**：网络恢复但 dataModel/spec 不变时，chunk 失败占位
  持续到下次 dataModel 更新（任务 6 修复轮固有语义）。
- **热更新重置卡片本地状态**：message.update 整批重播重建 processor——用户已输入但尚未经
  Button 上行的本地 dataModel 编辑、滚动/焦点等 UI 态会被合并帧状态重置（侦察 D3 指出的
  重置语义；计划裁决接受以保持"每卡独立 processor"不变，§4.2 末行）。
- **交互消息 turn 活跃时走 steering 队列**：动作回传是普通用户消息，turn 活跃时排队注入而非
  专用拦截（计划裁决接受的 MVP 行为；steering_mode 配置照常生效）。
